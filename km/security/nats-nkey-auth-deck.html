The problem

A factory network is crowded and high-stakes

The platform links thousands of machines, on-site servers, and cloud applications — often across many customer sites at once. Every one of them must be trusted, and kept inside its lane.

🪪Prove identity

Know exactly who or what is connecting. No impostors slipping in.

📈Scale across customers

Add a new factory without rewiring the central system or taking it offline.

🧯Contain the damage

If one device is compromised, it must not reach anything beyond its own job.

Passwords solve none of these well: they can be stolen, they pile up into a central list that becomes a prime target, and they say nothing about what the holder is allowed to do.
In technical termsThe classic failure modes of centralized credential stores and shared secrets, plus coarse, all-or-nothing access in a multi-tenant system.
The core idea

Replace passwords with unforgeable signatures

Each participant holds a matched pair: a private signature only it can produce, and a public sample anyone can use to check that signature.

never shared
🔏
Private signature

Stays with the holder

Impossible to forge or copy. The device uses it to sign — but never sends it to anyone, ever.

shared freely
🔎
Public sample

Everyone can hold a copy

Used only to verify a signature is genuine. It reveals nothing secret — useless on its own.

The central server keeps only the public samples. It stores no secret at all — so if the server is breached, there is nothing worth stealing.
In technical termsPublic-key cryptography. Each identity is an NKey (an Ed25519 keypair) — the public key is the identity, the private key is the seed. No secret material is stored server-side.
Chain of trust

Trust flows down from a single root

🏛️
Root authority — the platform
Kept offline in a vault. Vouches for each customer.
🏢
Customer — one per factory
Vouches for that factory's own devices and apps.
⚙️
Device or app
The actual machine or service connecting.

Each level stamps the one below it — like a government licensing a passport office, which in turn issues you a passport.

The server only has to trust the one root. Everyone else is vouched for down the chain — so onboarding a new customer never means reconfiguring the core system.

In technical termsA signing hierarchy — Operator → Account → User. Each level is a token signed by its parent's key; the server trusts only the pinned operator key.

🔱 Unforgeable seal from the issuer — break it and the card is void

The card states who you are and what you may do, sealed by the authority above it.

Change a single character and the seal breaks. It cannot be forged, and it cannot quietly grant itself more access.

In technical termsA JWT (JSON Web Token). The fields are claims; the seal is a cryptographic signature that makes it tamper-evident.
Connecting

← Signs the number, presents its ID card
Signed with its private signature, which never leaves the device.
SERVER
Checks the signature and the card's seals
Signature against the public sample; card against the chain of trust.

🛂Like a bouncer's check

You don't hand over a secret — you demonstrate you own one.

🔁Can't be replayed

The random number is different every time, so a captured login is worthless.

No password — and no secret of any kind — ever crosses the wire.
In technical termsA challenge–response handshake: the server sends a one-time nonce, the client signs it with its seed. Credentials sit in a local .creds file and never transit the wire.

🚫Locked by default

Nothing is permitted unless the card explicitly grants it. Every grant is checked against intent before a device ships.

📌Fixed when issued

Permissions are printed into the card. To change access, you reissue the card — leaving a clean, auditable trail.

A compromised sensor can still only do the one thing its card allows.
In technical termsAn ACL (Access Control List) — publish/subscribe allow-lists minted into each user's JWT. A credential can only reach the subjects it explicitly names; everything else is denied.
How it's deployed

Three layers: cloud, factory, machine

☁️ Cloud headquarters
The central system. Holds the one root of trust.
▲ secure outbound link
🏭 On-site factory relay
A local hub on the factory floor that gathers and forwards data.
▲ local network
⚙️ Machines & apps
Sensors, controllers, and the software that reads them.

🔌No inbound door

The factory relay only ever dials out to the cloud. Nothing on the outside can reach in.

📦Survives outages

If the internet link drops, the relay keeps collecting and forwards everything once it's back. No data lost.

In technical termsA hub cluster, edge leaf nodes, and clients. The leaf runs JetStream for store-and-forward, dialing out over WSS:443 — outbound-only, no inbound listener.
Running it day to day

Onboard, revoke, and guard the master key

➕Add a customer

Issue them an account and they're live — the running system keeps serving everyone else, with no downtime.

⛔Revoke a device

A lost or compromised device is cut off across the whole network within minutes.

🏦Master key in a vault

The root authority is kept offline. Daily work uses limited, delegated keys — so the crown jewels are never exposed.

👥Separation of duties

If a delegated key is stolen, it can be cancelled on its own — without ever touching the master key.

In technical termsThe root key lives in an HSM (Hardware Security Module); daily issuance uses delegated signing keys. Onboarding and revocation propagate through the account resolver with no restart.
The bottom line

What this buys the business

🛡️ Breach-resistantNo passwords or secrets stored centrally — a server breach has nothing to steal.
📈 Scales per customerOnboard new factories without downtime or reconfiguring the core system.
🧯 Built-in containmentLeast-privilege access limits the blast radius of any single compromise.
⛔ Instant revocationCut off one device — or a whole site — within minutes.
📋 Audit & compliance readyEvery identity and permission is explicit and traceable — suited to aerospace and defense requirements.
In technical termsOperator → Account → User trust, NKey identities carrying JWT-borne ACLs, an HSM-protected root, and a full account resolver for zero-downtime onboarding.
Where this stands. This is the target security model on the roadmap. It is being phased into the platform in stages; today's live demo uses a simpler interim scheme.
