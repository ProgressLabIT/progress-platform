<objective>
Add a dependency-free i18n key-parity check for the main webapp that compares
`src/i18n/en.js` against `src/i18n/it.js` and fails (non-zero exit) if either
locale is missing a key the other has. Wire it as a `yarn i18n:check` script.

Purpose: Prevent silent i18n drift (a real, observed problem — `it.js` already
carries keys like `active_qt` absent from `en.js`). Catch missing translations
before they ship.
Output:
- `webapps/main/scripts/check-i18n-parity.js` (new)
- `i18n:check` script in `webapps/main/package.json`
- Drift list recorded in SUMMARY if the check fails on the current tree
</objective>

webapps/main/package.json is ESM: `"type": "module"`. So a plain
`node scripts/check-i18n-parity.js` executes as ES modules — use `import`
statements and top-level `await` directly. No .mjs rename, no CJS require.

Both locale files export a nested object as the default export:

  // webapps/main/src/i18n/en.js  and  it.js
  export default {
    404: { alert: '…', productList: '…', … },
    login_page: { login_first: '…', … },
    active: '…',
    add: '…',
    bom: { add_line: '…', alerts: { line_exists: '…', … } },
    // …hundreds of keys, nested to several levels…
  }

Values are locale-specific translations (en English, it Italian) — they are
SUPPOSED to differ. Only the KEY SET must match. Do NOT compare values.

Vue-i18n pluralization uses pipe syntax in the string value (e.g.
`'all | tutti'`) — this lives inside the value, not the key, so it is
irrelevant to key parity. No special handling needed.

Known pre-existing drift signal (planner observed in file heads): `it.js` has
`active_qt` near the top; `en.js` does not. Expect the check to FAIL on the
current tree. That is the correct, intended behavior — handle it per Task 2.

<task type="auto">
  <name>Task 1: Write the dependency-free key-parity checker</name>
  <files>webapps/main/scripts/check-i18n-parity.js</files>
  <action>
Create `webapps/main/scripts/check-i18n-parity.js` as an ESM script (package
is `"type": "module"`, so `node scripts/check-i18n-parity.js` runs it as ESM —
use `import` and top-level `await`).

Behavior:
1. Dynamically import both locale modules relative to the script's own
   location (use `import.meta.url` + `new URL('../src/i18n/en.js', import.meta.url)`
   and the same for `it.js`), reading `.default` from each.
2. Recursively walk each object collecting the full set of dotted key paths
   (e.g. `bom.alerts.line_exists`, `404.alert`). Numeric object keys like `404`
   are fine as path segments. A "leaf" is any non-object value (string, or
   array — arrays are leaves, do not recurse into them). Recurse only into
   plain objects.
3. Compute the two set differences:
   - keys in en.js but MISSING from it.js
   - keys in it.js but MISSING from en.js
4. If both diffs are empty: print a one-line OK summary
   (`i18n parity OK — N keys match`) and `process.exit(0)`.
5. If either diff is non-empty: print a clear report — one line per missing
   key, grouped under a header naming which locale it is missing from
   (e.g. `Missing from it.js:` then the en-only keys, and
   `Missing from en.js:` then the it-only keys), print a count summary, then
   `process.exit(1)`.

Scope: KEY-PARITY ONLY. Do NOT compare values and do NOT flag identical-value
keys — values are locale-specific translations and comparing them would be all
false positives. This is the intended minimum.

No external dependencies — Node stdlib only (no `import` of any npm package).
Do not add any dependency to package.json.
  </action>
  <verify>
    <automated>cd webapps/main && node scripts/check-i18n-parity.js; echo "exit=$?"</automated>
  </verify>
  <done>
Script runs under node without throwing. It prints either an OK line (exit 0)
or a grouped list of missing dotted keys per locale (exit 1). No npm
dependencies added. Note the actual exit code + any drift list — it feeds
Task 2's branch and the SUMMARY.
  </done>
</task>

<task type="auto">

Then run the check to decide wiring (this is the intended, exercised failure/
success path — no synthetic tamper test needed):

- Run `cd webapps/main && yarn i18n:check` (or `node scripts/check-i18n-parity.js`).
- IF it EXITS 0 (parity clean): also chain it into the existing `lint` script
  so it runs alongside lint. Change:
    "lint": "yarn lint:check --fix"
  to:
    "lint": "yarn i18n:check && yarn lint:check --fix"

  carries keys absent from `en.js`): leave `lint` UNCHANGED. Do NOT break
  `yarn lint`. Keep `i18n:check` as a standalone task only. Record the full
  drift list (the missing keys per locale from the script output) in the
  SUMMARY under a "Pre-existing i18n drift (follow-up)" heading so it can be
  reconciled later.
