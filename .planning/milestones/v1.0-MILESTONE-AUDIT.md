### Integration Issues (Tech Debt)

1. **DIAL-02 port default:** `PrinterNew.vue` defaults port to `80`; ZPL printers use `9100`. Operators must correct manually.
2. **SVC-01 token context:** `verify_print_service_token` checks `USER_SESSION` context for service auth. Functionally works if print service user gets a `USER_SESSION` token with `print_service` scope — but semantically inconsistent.
3. **Warehouse config store latent gap:** `warehouse/src/stores/config.js` `updateAppConfig()` doesn't include template fields — harmless because `WarehouseSettings.vue` uses main app's config store.

## E2E Flow Verification

| Flow | Status | Path |
|------|--------|------|
| Main app — ZPL print | ✅ Complete | PrintDialog → generateZpl → sendToPrintService → POST /api/print-job → SSE → print service → TCP → result → waitForPrintResult → toast |
| Main app — PDF print | ✅ Complete | PrintDialog → generate() → chunked btoa (8192 chunks) → sendToPrintService → same SSE path |
| Warehouse product label | ✅ Complete | printProductLabel → resolveTemplateInputs → generateZpl → submitPrintJob → waitForPrintResult → theme-colored toast |
| Warehouse position label | ✅ Complete | printPositionLabel → same pattern |
| Template designer round-trip | ✅ Complete | Add field → linkType=template_expression → save (encodeTemplateExpressions) → reload (decodeTemplateExpressions) → print dialog resolves |

**Note on subscribe-before-submit race condition:** `waitForPrintResult` opens the EventSource subscription BEFORE `sendToPrintService` is called. This eliminates the race condition where the SSE result event could arrive before the listener was attached.
