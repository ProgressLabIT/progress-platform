# Requirements: Progress Platform Test Suite

**Defined:** 2026-04-09
**Core Value:** Catch regressions in the critical production event chain before they reach users

## v1 Requirements

Requirements for initial release. Each maps to roadmap phases.

### Test Infrastructure

- [ ] **INFRA-01**: Testcontainers spins up ArangoDB 3.11 container at session scope with automatic cleanup
- [ ] **INFRA-02**: Schema initialization creates all collections, edge collections, indexes, and default records (derived from `deploy/scripts/db_init.py`)
- [ ] **INFRA-03**: `db` singleton override injects testcontainer URL via env vars before backend import, clears `get_config` lru_cache
- [ ] **INFRA-04**: NATS `publish_sync` is mocked at session scope to prevent post-commit crashes
- [ ] **INFRA-05**: httpx.AsyncClient with ASGITransport provides in-memory API test client (no running server)
- [ ] **INFRA-06**: Auth JWT fixture generates valid tokens with configurable scopes (operator, planning, admin, etc.)
- [ ] **INFRA-07**: Collection truncation between tests ensures full isolation (edges before documents, respecting dependency order)
- [ ] **INFRA-08**: uv manages test suite dependencies via pyproject.toml with committed uv.lock

### Factory Fixtures

- [ ] **FACT-01**: User factory creates users with configurable scope strings (operator, planning, admin, quality, warehouse, etc.)
- [ ] **FACT-02**: Product factory creates products with configurable process (phases, operations, steps, form fields)
- [ ] **FACT-03**: BOM factory creates product bill-of-materials with component products (for consumption movement testing)
- [ ] **FACT-04**: WorkOrder factory creates work orders linked to products, with auto-generated WO codes
- [ ] **FACT-05**: Job factory creates jobs linked to work orders and phases, with configurable parameters (step_check, auto_new_batch, production_batch_qt, std_processing_time)
- [ ] **FACT-06**: Batch factory creates batches linked to jobs, with configurable quantities and status
- [ ] **FACT-07**: WorkSession factory creates work sessions linked to batches with duration and timestamps
- [ ] **FACT-08**: StepExecutionData factory creates step execution records with configurable form data
- [ ] **FACT-09**: Config document factory seeds required Config records (enable_inventory_management, default_production_position, default_consumption_position, default_operation_parameters)
- [ ] **FACT-10**: Parametrized builder combines flags (first_phase, last_phase, traceability_level, auto_new_batch, warehouse_management) to create correctly linked domain object graphs
- [ ] **FACT-11**: Serial factory creates serial records linked to products with configurable codes and counters
- [ ] **FACT-12**: WIP factory creates work-in-progress edge records between phases
- [ ] **FACT-13**: Inventory position factory creates positions with is_in_position records for stock
- [ ] **FACT-14**: Queue factory creates site and operator queue records for job assignment

### Backend Event Tests — StepCompletedEvent

- [ ] **STEP-01**: Happy path: completing a non-last step updates StepExecutionData to DONE status
- [ ] **STEP-02**: Last step triggers BatchCompletedEvent as child event
- [ ] **STEP-03**: Form data is correctly stored in StepExecutionData record
- [ ] **STEP-04**: Work session key is correctly set from current work session
- [ ] **STEP-05**: Temporary step data (existing StepExecutionData with no completion) is overwritten on completion
- [ ] **STEP-06**: Missing batch raises ValueError
- [ ] **STEP-07**: Response includes updated job data and batch execution data
- [ ] **STEP-08**: HTTP API integration test via POST endpoint exercises full dispatch chain

### Backend Event Tests — BatchCompletedEvent

- [ ] **BATCH-01**: Happy path: batch completion updates batch record (qt_pass, end timestamp), closes work session
- [ ] **BATCH-02**: Last batch (qt_completed >= qt_planned) triggers JobClosedEvent
- [ ] **BATCH-03**: Non-last batch with auto_new_batch creates new Batch + WorkSession automatically
- [ ] **BATCH-04**: Non-last batch without auto_new_batch sets job.active=False, active_batch_key=None
- [ ] **BATCH-05**: First phase does not generate WIPRemovedEvent
- [ ] **BATCH-06**: Non-first phase generates WIPRemovedEvent for completed quantity
- [ ] **BATCH-07**: Non-last phase generates WIPDeclaredEvent for downstream phase
- [ ] **BATCH-08**: Last phase triggers BatchReleasedEvent instead of WIPDeclared
- [ ] **BATCH-09**: With warehouse management enabled + last phase, generates production MovementCompletedEvent
- [ ] **BATCH-10**: With warehouse management enabled, generates consumption MovementCompletedEvent per BOM line
- [ ] **BATCH-11**: With traceability enabled, fetches batch serial keys and calls SerialUpdatedEvent per serial
- [ ] **BATCH-12**: With traceability + last phase, triggers SerialReleasedEvent per serial
- [ ] **BATCH-13**: Component serials trigger SerialLinkedEvent for each component
- [ ] **BATCH-14**: Step data without step_check stores batch execution data
- [ ] **BATCH-15**: Step data with step_check raises ValueError (must use StepCompletedEvent)
- [ ] **BATCH-16**: Quantity mismatch (batch.qt_total != completed_batch_qt) raises ValueError
- [ ] **BATCH-17**: Closed job raises ValueError
- [ ] **BATCH-18**: Serial code generation via counter when first_phase and serial has no code
- [ ] **BATCH-19**: Batch media files copied to serial directories
- [ ] **BATCH-20**: Parametrized matrix covers key flag combinations (first/last phase x traceability x warehouse x auto_new_batch)
- [ ] **BATCH-21**: HTTP API integration test exercises full cascade through endpoint

### Backend Event Tests — ProgressOverrideRequestedEvent

- [ ] **PROG-01**: Quantity increase creates forced batch, work session, and downstream WIP
- [ ] **PROG-02**: Quantity decrease cancels batches newest-to-oldest until target reached
- [ ] **PROG-03**: Quantity decrease creates compensating batch when over-canceled
- [ ] **PROG-04**: Time redistribution creates new work sessions with proportional durations when should_adjust_duration=False
- [ ] **PROG-05**: Job transitions: CREATED->STARTED on first increase, STARTED->CLOSED when complete
- [ ] **PROG-06**: Job transitions: CLOSED->STARTED on decrease (reopening), STARTED->CREATED when quantity=0
- [ ] **PROG-07**: Reopened job is re-added to operator queue and site queue reordered
- [ ] **PROG-08**: Upstream WIP reduced on quantity increase (non-first phase)
- [ ] **PROG-09**: Downstream WIP reduced on quantity decrease (non-last phase)
- [ ] **PROG-10**: Inventory movements created for forced batches when warehouse management enabled
- [ ] **PROG-11**: Inventory movements reversed for canceled batches
- [ ] **PROG-12**: Validation: no assignee raises JobHasNoAssigneeError
- [ ] **PROG-13**: Validation: active job raises JobIsActiveError
- [ ] **PROG-14**: Validation: active batch raises JobHasActiveBatchError
- [ ] **PROG-15**: Validation: traceability enabled raises NotImplementedError
- [ ] **PROG-16**: Validation: insufficient upstream WIP raises WipNotAvailableError
- [ ] **PROG-17**: HTTP API integration test exercises override flow through endpoint

- [ ] **MOVE-01**: Receipt adds product to destination position inventory
- [ ] **MOVE-02**: Receipt with traceability creates or finds serial, validates serial code required
- [ ] **MOVE-03**: Receipt with existing serial already in inventory raises InventoryMovementException
- [ ] **MOVE-04**: Shipment removes product from source position inventory
- [ ] **MOVE-05**: Shipment with traceability validates serial_key required
- [ ] **MOVE-06**: Shipment from position with insufficient inventory raises InventoryMovementException
- [ ] **MOVE-07**: Adjustment adds/removes quantity at position
- [ ] **MOVE-08**: Product transfer updates both source and destination positions
- [ ] **MOVE-09**: Container transfer updates position hierarchy without moving product
- [ ] **MOVE-10**: Fixed position cannot be container-transferred
- [ ] **MOVE-11**: Production movement (position_from=NULL) creates inventory at destination
- [ ] **MOVE-12**: Consumption movement (position_to=NULL) removes inventory from source
- [ ] **MOVE-13**: Reversal type raises InventoryMovementException (must use MOVEMENT_REVERSED)
- [ ] **MOVE-14**: Deleted position raises error
- [ ] **MOVE-15**: Planned movement (existing movement_key) updates to COMPLETED status
- [ ] **MOVE-16**: HTTP API integration test exercises movement flow through endpoint

## Out of Scope

| Feature | Reason |
|---------|--------|
| Backfilling tests on all existing code | Testing strategy: grow coverage from the frontier, not backfill |
| Mobile warehouse app (Capacitor) testing | Separate app with different testing concerns; defer |
| Replacing existing Mocha/Cypress/Robot tests | New suite runs alongside; old tests deprecated organically |
| Microcks contract testing | No clear benefit identified in research |
| factory_boy ORM-style factories | ArangoDB is document DB; plain fixture functions are more appropriate |
| Mocking ArangoDB | Testing strategy principle #4: real database, not mocks |
