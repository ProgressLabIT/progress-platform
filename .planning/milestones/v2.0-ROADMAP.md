# Roadmap: Progress Platform Test Suite

## Overview

Four phases build the complete test suite from the ground up. Phase 1 lays the infrastructure foundation that everything depends on — the ArangoDB testcontainer, db singleton override, NATS mock, and factory fixtures. Phase 2 delivers deep dual-layer tests for the critical production event cascade. Phase 3 adds API quality enforcement via OpenAPI audit and Schemathesis fuzzing, plus Locust load scenarios. Phase 4 covers the frontend independently with Vitest component tests and Playwright E2E journeys.

## Phase Details

### Phase 1: Infrastructure + Fixtures
**Goal**: A working test harness exists — pytest can spin up a real ArangoDB, override the db singleton before any backend import, mock NATS, initialize the full schema, isolate tests via truncation, and build any domain object graph via factory fixtures
**Depends on**: Nothing (first phase)
**Requirements**: INFRA-01, INFRA-02, INFRA-03, INFRA-04, INFRA-05, INFRA-06, INFRA-07, INFRA-08, FACT-01, FACT-02, FACT-03, FACT-04, FACT-05, FACT-06, FACT-07, FACT-08, FACT-09, FACT-10, FACT-11, FACT-12, FACT-13, FACT-14
**Success Criteria** (what must be TRUE):
  1. Running `pytest testing/` starts an ArangoDB 3.11 container, initializes all collections/indexes, and tears down cleanly after the session
  2. A smoke test can create a full WorkOrder -> Job -> Batch -> WorkSession -> StepExecutionData graph using factory fixtures, with no manual DB setup
  3. Each test class starts with empty collections — data inserted by one test is not visible in the next
  4. NATS publish calls do not raise exceptions during or after event dispatch in tests
  5. uv manages all test dependencies; `uv sync` is the only setup step required
**Plans:** 4 plans
Plans:
- [x] 01-01-PLAN.md — uv project setup, schema helper extraction, root conftest with all infrastructure fixtures
- [x] 01-02-PLAN.md — Infrastructure smoke tests validating the harness

- [x] 01-04-PLAN.md — Advanced factories (Serial, WIP, Position, Queue, parametrized builder) + factory smoke tests

**Success Criteria** (what must be TRUE):
  1. A StepCompletedEvent test suite runs 8 cases (happy path, last-step trigger, form data, work session key, overwrite, missing batch error, response shape, HTTP endpoint) all passing
  2. A BatchCompletedEvent test suite covers the 32-combination parametrize matrix (first/last phase x traceability x warehouse x auto_new_batch) with all branches verified via Config document smoke assertions

### Phase 3: API Quality + Load
**Goal**: The OpenAPI spec is complete and correct, Schemathesis fuzzing runs without crashes against it, and Locust scenarios confirm the critical endpoints hold under concurrent load
**Depends on**: Phase 2
**Requirements**: SPEC-01, SPEC-02, SPEC-03, SPEC-04, SPEC-05, SPEC-06, LOAD-01, LOAD-02, LOAD-03
**Success Criteria** (what must be TRUE):
  1. Every endpoint in the FastAPI app has an input Pydantic model, an output response model, and a docstring — confirmed by an audit script or test that fails on missing schemas
  2. `GET /openapi.json` returns a document that validates against the OpenAPI 3.x specification
  3. Schemathesis runs via `from_asgi()` against all endpoints without crashing, and no 5xx responses occur on valid inputs
  4. Three Locust scenarios (batch completion, inventory movement, production queries) can be executed and produce throughput/latency output
