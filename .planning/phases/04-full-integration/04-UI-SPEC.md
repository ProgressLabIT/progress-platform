## Spacing Scale

Declared values (must be multiples of 4). Quasar utility classes map directly to these.

| Token | Value | Usage | Quasar class |
|-------|-------|-------|--------------|
| xs | 4px | Icon gaps, inline padding | q-pa-xs, q-ma-xs |
| sm | 8px | Compact element spacing, q-gutter-sm in nav rows | q-pa-sm, q-gutter-sm |
| md | 16px | Default field spacing, card sections | q-pa-md, q-mt-md |
| lg | 24px | Section padding, dialog inner padding | q-pa-lg |
| xl | 32px | Layout gaps between major sections | q-pa-xl |
| 2xl | 48px | Major section breaks | — |
| 3xl | 64px | Page-level spacing | — |

Exceptions:
- `q-stepper-navigation` uses `class="flex q-gutter-sm"` (8px gaps between buttons) — matches existing PrintDialog.vue step navigation pattern.
- Touch targets for icon-only buttons: minimum 44px height (Quasar default `q-btn` dense=false satisfies this).

Source: existing `PrintDialog.vue` stepper navigation, `PrinterNew.vue` form fields.

## Typography

All sizes use **Red Hat Text**. Orbitron is reserved for `.display` brand elements only — do not apply to new form labels, table columns, or dialog copy.

| Role | Size | Weight | Line Height | Usage in Phase 4 |
|------|------|--------|-------------|-----------------|
| Body | 16px (1rem) | 400 (regular) | 1.2 | Form field values, table cell content, toast message body |
| Label | 14px (0.875rem) | 500 (medium) | 1.2 | Form field labels (`q-input` label prop), table column headers, q-tab labels |
| Heading | ~18.7px (1.17rem) | 500 (medium) | 1.2 | Dialog section headers using `.text-h3` |
| Overline | ~10.7px (0.67rem) | 700 (bold), uppercase | 1.2 | Column category labels using `.overline` class |

Source: `typography.scss` — `.text-h3 { font-size: 1.17rem; font-weight: 500 }`, `.q-tab { font-size: 0.875rem; font-weight: 500 }`, `body { line-height: 1.2 }`.

## Color

Dark theme only. This app uses `progress-theme="dark"` with custom CSS variables.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#131e21` (background) / `#1f2a2d` (surface1) | Page background, dialog background, stepper body |
| Secondary (30%) | `#242e31` (surface2) | Cards, form field fill backgrounds, table rows |
| Accent (10%) | `#22aed1` (theme-blue / $primary) | See reserved list below |
| Positive | `#21ba45` ($positive) | Success toast (Notify type: 'positive') |
| Negative / Destructive | `#c10015` ($negative) | Error toast (Notify type: 'negative'), required field indicators |

**Accent (`#22aed1`) reserved for:**
- Primary action buttons: "Send to [printer name]" button (`color="primary"`)
- Active stepper step indicator
- "Next" / confirm buttons that advance the print workflow

**Accent NOT used for:**
- Cancel, back, or secondary navigation buttons (use `color="theme-grey"` / `#707070`)
- Table column values or passive labels
- The spinner during printing in-progress state (use Quasar default spinner color)

**Semantic colors:**
- Positive (`#21ba45`): success print toast only
- Negative (`#c10015`): error/timeout print toast, required field star indicator

Source: `quasar.variables.scss`, `theme.scss`, existing `PrintDialog.vue` button color patterns.

## Component Inventory

New and modified components for this phase. Implementors must match these patterns exactly.

### PrintDialog.vue — Step 3 additions

**States:**

| State | Visual |
|-------|--------|
| Default | "Download PDF" button (existing, `color="primary"`) + "Send to [name]" button (`color="primary"`) — both visible when `selectedPrinter !== null` |
| No printer configured | "Send to Printer" button hidden; only "Download PDF" shown |
| Printing in-progress | Both buttons hidden; `q-spinner color="primary" size="2em"` centered in stepper navigation; no other controls active |
| Result (success/error) | Dialog closes; Quasar `Notify.create()` toast appears |
| Timeout | Dialog closes; negative toast appears |

**Button layout in `q-stepper-navigation`:**
```
[Cancel]  [spacer]  [Back]  [Download PDF]  [Send to {name}]
                            ← both right-aligned, 8px gap (q-gutter-sm)
```

During printing:
```
[spacer]  [q-spinner]
          ← centered
```

**"Send to Printer" button spec:**
- Label: `"Send to [printer.name]"` — e.g. "Send to Zebra ZD420"
- Icon: `mdi-printer-pos-send` (or `mdi-printer` if unavailable in project MDI version)
- Color: `primary` (`#22aed1`)
- Only rendered when `selectedPrinter !== null`

### PrinterNew.vue — new fields

**`type` field:**
- Component: `q-select`
- Label: `$t('printer.type')` (new i18n key)
- Options: `[{ label: 'ZPL', value: 'zpl' }, { label: 'PDF', value: 'pdf' }]`
- Required: yes (validation rule: `!!value || $t('field_required_alert')`)
- No default value — user must explicitly select
- Filled style, `class="q-mt-md"` (matches existing `q-input` pattern in same file)

**`timeout_seconds` field:**
- Component: `q-input` with `type="number"`
- Label: `$t('printer.timeout_seconds')` (new i18n key)
- Default value: `5`
- Min: `1`
- Filled style, `class="q-mt-md"`

2. **Timeout** — display as `"{n}s"` (e.g. `"5s"`)

Column header copy:
- Type: `$t('printer.type')`
- Timeout: `$t('printer.timeout')`

### WarehouseSettings.vue — template selector section

A new section below existing warehouse settings content. Two `q-select` fields:

|-------|-------|----------|
| Product label template | "Product label template" | `settings.warehouse.productLabelTemplate` |

| Event | type | message |
|-------|------|---------|
| Print success | `positive` | `$t('printDialog.sendToPrinter.success')` → "Label sent to printer" |

## Interaction Contracts

### "Send to Printer" — state machine

```
[Step 3 default]
  selectedPrinter !== null
  → Show "Download PDF" + "Send to [name]"

[User clicks "Send to [name]"]
  → Set isPrinting = true
  → Hide both buttons
  → Show q-spinner (centered in nav row)
  → POST /api/print-job
  → Open EventSource on /notification/print-result
  → Wait for event where event.data.job_id === returned job_id
  → Timeout = (printer.timeout_seconds + 5) * 1000 ms

[SSE event arrives — ok: true]
  → Close EventSource
  → onDialogHide()
  → Notify.create({ type: 'positive', message: t('printDialog.sendToPrinter.success') })

[SSE event arrives — ok: false]
  → Close EventSource
  → onDialogHide()
  → Notify.create({ type: 'negative', message: result.detail || t('printDialog.sendToPrinter.error') })

[Timeout reached]
  → Close EventSource
  → onDialogHide()
  → Notify.create({ type: 'negative', message: t('printDialog.sendToPrinter.timeout') })

[POST fails (network/API error)]
  → isPrinting = false (reset to default state)
  → Show error inline OR Notify.create negative toast
  → Dialog stays open (user can retry)
```

### Printer type routing

```
selectedPrinter.type === 'zpl'
  → generateZpl(template, inputs, { dpi: 203, quantity: copies })
  → sendToPrintService({ data: zplString, printer, format: 'zpl', copies })

selectedPrinter.type === 'pdf'
  → generate(template, inputs, plugins)  // returns Uint8Array
  → base64 = btoa(String.fromCharCode(...pdfBytes))
  → sendToPrintService({ data: base64, printer, format: 'pdf', copies })
```

### Warehouse operator UX (no visible change)

The operator sees the same button/click flow as before. No new steps, no new prompts. The underlying call changes from BrowserPrint → `POST /api/print-job`, but the visual layer is unchanged.
