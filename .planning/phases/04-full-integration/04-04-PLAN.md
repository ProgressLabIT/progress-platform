**Required sections (all six topics from DOC-01):**

**1. Template String Fields**
- Syntax: `{{variable}}` composite text in pdfme designer
- Storage format: encoded as `{{cf::_key}}` for custom fields, `{{preset_name}}` for presets
- Designer behavior: decoded to human-readable labels on load, encoded on save
- Resolution: `resolveExpression()` replaces `{{tokens}}` with live data at print time
- Link type: `template_expression` on field schema

**2. ZPL Transpiler**
- Function: `generateZpl(template, inputs, { dpi, quantity })`
- Location: `webapps/main/src/lib/print/zpl.js`
- Supported field types and their ZPL commands:
  - text/template_string: `^A0N` + `^FB` (scalable font + field block)
  - qrcode: `^BQN` (QR Code model 2)
  - code128: `^BCN`
  - code39: `^B3N`
  - ean13: `^BEN` (pass 12 digits, printer computes check digit)
  - gs1datamatrix: `^BXN` (DataMatrix ECC 200)
  - image: silently skipped with console.warn (deferred to v3)
- Coordinate conversion: mm to dots via `mm * (dpi / 25.4)`, default DPI 203
- Output: `^XA ... ^PQ{quantity} ^XZ` envelope per page

**3. Print Service**
- Architecture: Browser -> Main API (POST /api/print-job) -> SSE -> Print Service -> TCP -> Printer -> Result callback -> SSE -> Browser toast
- The browser NEVER calls the print service directly
- Deployment: `deploy/compose/print.yaml`
  - Docker image from `backend/print-service/Dockerfile`
  - Environment variables: `PRINT_SERVICE_API_URL` (main API public URL with /api), `PRINT_SERVICE_API_TOKEN` (non-expiring JWT for service user)
  - `traefik.enable=false`, no inbound ports required (outbound connections only)
  - Health endpoint on `:8200` (checks SSE subscription status)
- API contract:
  - `POST /api/print-job`: body `{ printer_host, printer_port, format, data, copies, timeout_seconds }`; returns `{ job_id }`
  - `GET /api/print-jobs/stream`: SSE stream for print service subscription (authenticated)
  - `POST /api/print-jobs/{id}/result`: callback from print service with `{ ok, error, detail }`
- SSE feedback: `/notification/print-result` with subtopic `print-result`, payload `{ job_id, ok, error, detail }`
- TCP error classification: `connection_refused`, `timeout`, `send_error`

**4. Printer Type Field**
- Each printer now has `type` (required: `zpl` or `pdf`) and `timeout_seconds` (default 5)
- Set in Settings > Printers when adding a printer
- `type` determines the print path:
  - `zpl`: `generateZpl()` produces ZPL string, sent as-is
  - `pdf`: `@pdfme/generator` produces PDF bytes, base64-encoded, sent as PDF
- `timeout_seconds` controls how long the print service waits for TCP response, and the frontend waits `timeout_seconds + 5` seconds for the SSE result

**5. Print Dialog "Send to Printer"**
- Visible when user has a printer configured in their preferences (Settings > Printers > select one)
- Button label: "Send to [printer name]" — shows the configured printer's name
- No printer selector dropdown in the dialog — uses the user's preference
- Flow: click -> spinner -> POST /api/print-job -> SSE wait -> close dialog + toast
- Success: green toast "Label sent to printer"
- Error: red toast with error detail
- Timeout: red toast "No response from printer"
- Download PDF button preserved alongside — both options available

**6. Warehouse Template Assignment**
- Settings > Warehouse Settings has two template selectors: Product label template, Position label template
- These are independent of the inventory management toggle
- Saved to config as `product_label_template` and `position_label_template` keys
- Warehouse app reads these at print time to fetch the template, resolve fields, generate ZPL, and POST to /api/print-job
- Warehouse preset contexts: `product.code`, `product.description` for product labels; `position.code` for position labels
- Operator UX unchanged — same buttons, same behavior, backed by new architecture
- BrowserPrint / `/pstprnt` dependency fully removed
