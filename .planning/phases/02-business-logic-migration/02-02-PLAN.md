<objective>
Migrate float quantity comparisons in WIP events to use tolerance-based comparison utilities, preventing off-by-epsilon issues in WIP booking/unbooking logic.

**Purpose**: Ensure that quantities like 99.999999 and 100.0 are treated as equal in WIP operations, preventing incorrect partial bookings or errors due to floating-point precision noise.

**Output**:
- 3 WIP event files updated with tolerance comparisons
- Inline comments explaining tolerance usage
- Consistent epsilon handling across all WIP operations
</objective>
