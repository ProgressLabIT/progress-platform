## Research Findings — Schemathesis v4 API

### Package: schemathesis 4.15.1 (latest, pin to >=4.15)
No `schemathesis.from_asgi` at top level in v4. Correct entrypoint:
```python
import schemathesis
schema = schemathesis.openapi.from_asgi("/openapi.json", app)
```

Signature: `from_asgi(path: str, app: Any, *, config: SchemathesisConfig | None = None, **kwargs) -> OpenApiSchema`

### Auth Injection — v4 Pattern
v4 uses `@schemathesis.auth()` class decorator to register a global auth provider:

```python
@schemathesis.auth()
class JWTAuth:
    def get(self, case, ctx):
        return "Bearer test-token"

    def set(self, case, data, ctx):
        case.headers = case.headers or {}
        case.headers["Authorization"] = data
```

The `get()` method returns the auth value; `set()` applies it to the `Case` object. This is registered globally, so it applies to all test cases generated by `schema.parametrize()`.

However, the dependency override (`app.dependency_overrides[verify_token]`) must also be active so the backend accepts the token. Since our `auth_headers` fixture manages overrides at function scope and Schemathesis drives multiple cases per parametrized test run, we set the override in a session-scoped fixture and clear it after.

### Fixture-Based Schema Loading (v4 pattern)
Use `schemathesis.pytest.from_fixture("api_schema")` to load the schema lazily from a pytest fixture, so the fixture can depend on `db` and `mock_nats` (ensuring backend is initialized):

```python
@pytest.fixture(scope="session")
def api_schema(db, mock_nats):
    from main import app
    return schemathesis.openapi.from_asgi("/openapi.json", app)

schema = schemathesis.pytest.from_fixture("api_schema")

@schema.parametrize()
def test_api(case):
    case.call_and_validate()
```

### Route Exclusions
Routes excluded from fuzzing (added to schema filter or pyproject.toml schemathesis config):
- `/notification/{topic}` — SSE endpoint, Schemathesis cannot handle EventSourceResponse stream
- `/media/` (POST) and `/media/{media_key}` (PATCH) — UploadFile multipart
- `/org/{org_key}/image` — UploadFile multipart
- `/config/{key}/file` — UploadFile multipart
- `/count-session/{session_key}/import` — UploadFile multipart

Exclusion mechanism: use `schema.filter_operations()` hook or the `exclude` parameter on `from_asgi`. In v4, the cleanest approach is a `@schema.parametrize()` with an `@schemathesis.hooks.hook` or using the `exclude` parameter via `FilterSet`. Simplest: use the `schema.configure()` with `suppress_health_check` or filter using a before-test hook that skips multipart/SSE paths.

Actually the cleanest v4 mechanism: call `schema.exclude(path_regex=...)` after loading, or use `schema.filter_operations()`. Check v4:
- `schema.filter_operations(lambda op: not op.path.startswith("/notification"))` is available on `BaseSchema`

Use `schema.exclude()` if available, else filter with a `@schema.parametrize(filter_operations=...)` pattern. If neither is clean, set `case.skip()` inside the test body when the path matches exclusion list.

### FastAPI OpenAPI path
FastAPI serves OpenAPI at `/openapi.json` by default (no `root_path` prefix in the test transport). Confirmed: `app = FastAPI(root_path=config.api_root_path)` — the `root_path` is for reverse proxy path prefixing, not the internal OpenAPI URL. The schema endpoint is `/openapi.json` in the ASGI app's internal routing.

### 5xx vs 422 check
`case.call_and_validate()` with default checks will fail on 5xx. 422 (Unprocessable Entity) is the FastAPI default for schema validation failures — Schemathesis v4's `not_a_server_error` check (the default) passes on 422. So default behavior is correct: fails on 5xx, passes on 422.

```python
"""Schemathesis fuzzing test — fail on any 5xx response to generated inputs.

Uses schemathesis.openapi.from_asgi() (v4 API) to load the OpenAPI schema from
the in-process FastAPI app. Auth is injected via the @schemathesis.auth() provider
pattern which sets the Authorization header and activates the verify_token
dependency override on each generated case.

Decisions: D-06 through D-11 (context doc).
- 5xx responses → test failure
- 401 responses → test failure (indicates auth injection broken)
- 422 responses → pass (expected from fuzzing with invalid payloads)
- Excluded routes: SSE (/notification/), multipart file uploads
"""
import pytest
import schemathesis
from schemathesis import AuthContext, Case

# ---------------------------------------------------------------------------
# Excluded route patterns — SSE and multipart file upload endpoints
# ---------------------------------------------------------------------------
_EXCLUDED_PATHS = {
    "/notification/{topic}",  # SSE stream — EventSourceResponse
    "/media/",               # POST UploadFile
    "/media/{media_key}",    # PATCH UploadFile
    "/org/{org_key}/image",  # POST UploadFile
    "/config/{key}/file",    # POST UploadFile
    "/count-session/{session_key}/import",  # POST UploadFile + Form
}


# ---------------------------------------------------------------------------
# Auth provider — injects JWT header + FastAPI dependency override
# ---------------------------------------------------------------------------
@schemathesis.auth()
class ProgressJWTAuth:
    """Inject a fixture JWT token into every generated Schemathesis test case.

    get() returns the header value string.
    set() applies it to case.headers and activates the dependency override so
    FastAPI's verify_token returns a valid TokenData without hitting the DB.
    """

    def get(self, case: Case, ctx: AuthContext) -> str:
        return "Bearer test-token"

    def set(self, case: Case, data: str, ctx: AuthContext) -> None:
        from main import app
        from utils.auth import verify_token
        from models.auth import TokenData, TokenContext
        from datetime import datetime, timedelta

        # Build a fully scoped token for the request
        token_data = TokenData(
            jti="schemathesis-token",
            sub="schemathesis-user",
            ctyp="user",
            iat=datetime.utcnow(),
            exp=datetime.utcnow() + timedelta(hours=1),
            ctx=TokenContext.USER_SESSION,
            scope="operator production admin quality warehouse",
        )
        app.dependency_overrides[verify_token] = lambda: token_data

        # Set the header on the case
        if case.headers is None:
            case.headers = {}
        case.headers["Authorization"] = data


# ---------------------------------------------------------------------------
# Schema fixture — depends on db + mock_nats so backend is fully initialized
# ---------------------------------------------------------------------------
@pytest.fixture(scope="session")
def api_schema(db, mock_nats):
    """Load OpenAPI schema from the ASGI app in-process."""
    from main import app
    return schemathesis.openapi.from_asgi("/openapi.json", app)


# Lazy fixture reference — Schemathesis resolves this at test collection time
schema = schemathesis.pytest.from_fixture("api_schema")


# ---------------------------------------------------------------------------
# Fuzz test
# ---------------------------------------------------------------------------
@schema.parametrize()
def test_api_fuzzing(case):
    """Fuzz all non-excluded API endpoints. Fail on 5xx or 401."""
    # Skip excluded routes (SSE, multipart uploads)
    if case.path in _EXCLUDED_PATHS:
        pytest.skip(f"Excluded from fuzzing: {case.path}")

    response = case.call()

    # 5xx = server crash or unhandled error → failure
    assert response.status_code < 500, (
        f"Server error on {case.method} {case.path}: "
        f"HTTP {response.status_code}\n{response.text[:500]}"
    )

    # 401 = auth injection broken → failure
    assert response.status_code != 401, (
        f"Auth injection failed on {case.method} {case.path}: "
        f"HTTP {response.status_code}"
    )
    # 422 = FastAPI validation rejection of fuzzed input → expected, pass silently
```

Key implementation notes:
- Use `case.call()` (not `case.call_and_validate()`) so we can assert specific status codes with clear messages rather than Schemathesis's built-in check names.
- `ProgressJWTAuth.set()` rebuilds `app.dependency_overrides[verify_token]` on each case — safe because ASGI test calls are synchronous from Schemathesis's perspective.
- `scope="session"` on `api_schema` fixture ensures the ASGI schema is loaded once.
- `schemathesis.pytest.from_fixture("api_schema")` is the v4 mechanism for fixture-based lazy schema loading.
