## Task 1 — `.github/workflows/deploy-docs.yml` (per RESEARCH.md §F.1)

Lift verbatim. CP-9 enforced (`fetch-depth: 0` for `lastUpdated: true` to populate sitemap `<lastmod>`). Cache scoped to `docs/package-lock.json` (yarn.lock at repo root is unrelated). Path filter prevents needless deploys on backend-only PRs.

```yaml
# .github/workflows/deploy-docs.yml
name: Deploy VitePress site to Pages

on:
  push:
    branches: [DEV]
    paths:
      - 'docs/**'
      - '.github/workflows/deploy-docs.yml'
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

# Allow only one concurrent deployment; do NOT cancel mid-flight (partial-deploy risk)
concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: docs
    steps:
      - name: Checkout
        uses: actions/checkout@v5
        with:
          fetch-depth: 0   # CP-9: VitePress lastUpdated needs full git history

      - name: Setup Node
        uses: actions/setup-node@v6
        with:
          node-version: 20.19.0
          cache: npm
          cache-dependency-path: docs/package-lock.json

      - name: Setup Pages
        uses: actions/configure-pages@v5

      - name: Cache VitePress build
        uses: actions/cache@v4
        with:
          path: docs/.vitepress/cache
          key: vitepress-${{ runner.os }}-${{ hashFiles('docs/package-lock.json', 'docs/.vitepress/config.ts') }}
          restore-keys: |
            vitepress-${{ runner.os }}-

      - name: Install dependencies
        run: npm ci

      - name: Build with VitePress
        run: npm run docs:build

      - name: Upload artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: docs/.vitepress/dist

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

Job name `build` matches the `required_status_checks` context set by plan 01-01 Task 7. Do NOT rename without updating the ruleset.

## Task 2 — `.github/workflows/lychee.yml` + `lychee.toml` (per RESEARCH.md §F.2 + Pitfall 1.4)

`.github/workflows/lychee.yml`:

```yaml
# .github/workflows/lychee.yml
name: lychee dead-link check

on:
  pull_request:
    paths:
      - 'docs/**'
      - '.github/workflows/lychee.yml'
      - 'lychee.toml'
  push:
    branches: [DEV]
    paths:
      - 'docs/**'
      - 'lychee.toml'

jobs:
  linkChecker:
    runs-on: ubuntu-latest
    permissions:
      contents: read
    steps:
      - name: Checkout
        uses: actions/checkout@v5

      - name: Setup Node
        uses: actions/setup-node@v6
        with:
          node-version: 20.19.0
          cache: npm
          cache-dependency-path: docs/package-lock.json

      - name: Install
        working-directory: docs
        run: npm ci

      - name: Build with VitePress
        working-directory: docs
        run: npm run docs:build

      - name: lychee link check (anchor-aware)
        uses: lycheeverse/lychee-action@v2
        with:
          # Pitfall 1.4: --include-fragments enables hash-anchor validation
          # CP-10: --root-dir + --base resolve internal /progress-platform/* against dist/
          args: >-
            --no-progress
            --include-fragments
            --root-dir "${{ github.workspace }}/docs/.vitepress/dist"
            --base "https://progresslabit.github.io/progress-platform/"
            --config "${{ github.workspace }}/lychee.toml"
            "docs/.vitepress/dist/**/*.html"
          fail: true
          jobSummary: true
```

Job name `linkChecker` matches the ruleset context from plan 01-01.

`lychee.toml` (declarative supplement; CLI flags above already work standalone but this captures excludes in code-review-able form):

```toml
# lychee.toml
# Phase 1 — exclude localhost variants so README dev-stack samples don't fail CI.

exclude = [
  "^https?://(?:localhost|127\\.0\\.0\\.1|progress\\.localhost)",
]

# Tolerate a few common rate-limited CDNs without failing CI.
exclude_all_private = true

# Cache to reduce upstream load on rerun.
cache = true
max_cache_age = "2d"
```

CP-10 enforcement: the action's `args` MUST include both `--root-dir` AND `--base`. Without these, every internal absolute link beginning with `/progress-platform/...` resolves against `https://github.com/...` and fails — false-positive avalanche.

```yaml
      - "dependencies"
      - "ci"
```

<threat_model>

ASVS L1; block on `high`. CI workflows have elevated privileges (Pages publish, OIDC token); supply-chain attacks via Action versions are the primary concern.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Action runner → GitHub Pages CDN | OIDC `id-token: write` lets the runner mint a Pages-publish token; misconfiguration leaks publish capability |
| Action version → workflow | each `uses:` line trusts an external repo at a tag/SHA |
| `npm ci` → runner | transitive npm packages execute scripts during install (mitigation: pinned via `package-lock.json` from 01-02; future hardening: `npm ci --ignore-scripts`) |
| Lychee CLI → external HTTP | crawls every link in `dist/` — outbound only; no inbound surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03-01 | Elevation of Privilege | `permissions:` block on `deploy-docs.yml` granting `contents: write` would let the workflow push back to the repo | mitigate | Permissions block scoped to `contents: read`, `pages: write`, `id-token: write`. No `contents: write`, no `actions: write`. Lychee workflow uses `contents: read` only. |
| T-01-03-02 | Tampering | Action pinned to floating major tag (e.g. `lycheeverse/lychee-action@v2`) — silent compromise of upstream fork would compromise our CI | mitigate | All Actions pinned to majors per official VitePress / lychee guidance. **Post-launch hardening (Phase 4 admin item): switch to SHA pins** per lychee's own README recommendation. Tracked in `.planning/workstreams/docs/STATE.md` under `Post-Launch TODOs` (W2 deferral); NOT in v1 scope. |
| T-01-03-03 | Tampering | Pages deploy from a forked-PR branch (would let any PR author publish to the production Pages site) | mitigate | `deploy-docs.yml` triggers ONLY on `push: branches: [DEV]` and `workflow_dispatch`. PRs do not trigger it — they only trigger lychee, which has `contents: read` and no Pages access. |
| T-01-03-04 | Tampering | Unpinned npm transitive that triggers a malicious lifecycle script during `npm ci` | accept (post-launch hardening) | `npm ci` respects `package-lock.json` integrity hashes (set in 01-02). Dependabot surfaces advisories. **Post-launch:** consider `npm ci --ignore-scripts` once we audit which packages need install scripts. |
| T-01-03-05 | Information Disclosure | `lychee` crawls site and could leak internal URLs to external hosts via redirects | accept | Phase 1 site has no internal URLs — every page is public OSS scaffold. `lychee.toml` excludes `localhost`/`127.0.0.1` patterns from being followed (those would be false positives anyway). |
| T-01-03-06 | Denial of Service | Concurrent deploys racing partial-deploy state | mitigate | `concurrency: { group: pages, cancel-in-progress: false }` — queue but don't cancel mid-flight (per VitePress official guidance). |
| T-01-03-07 | Information Disclosure | Build artifact contains `.env` / secrets | accept | Phase 1 docs site has no env consumption; `vitepress build` reads only files in the repo. No secrets in `docs/`. |
| T-01-03-08 | Tampering | Branch protection misconfigured such that mirror push silently fails (CP-8) | mitigate | Plan 01-01 Task 7 explicitly excluded the offending rule (`pull_request_required`). Plan 01-03 Task 5 verifies the post-deploy state with `git ls-remote DEV` SHA-match. |

No `high`-severity threats remain after mitigation. Plan exits ASVS L1 block-on-high gate.

```bash
# === Anchor 4: Push triggers Actions deploy in <10 min ===

# Latest deploy-docs run state and elapsed wall-time
gh run list --repo ProgressLabIT/progress-platform --workflow=deploy-docs.yml --limit 1 \
  --json status,conclusion,startedAt,updatedAt,databaseId,htmlUrl \
  | jq -e '.[0].conclusion == "success"
           and ((.[0].updatedAt | fromdateiso8601) - (.[0].startedAt | fromdateiso8601)) < 600'

# === Anchor 4: Pages site reachable; HTTP 200 on every contract URL ===

BASE=https://progresslabit.github.io/progress-platform
for path in / /api/ /api/production/jobs/start/ /events/ /events/production/job-started/ \
            /cli/ /cli/init/ /users/ /users/production/ /admins/ /admins/deployment/; do
  STATUS=$(curl -fsS -o /dev/null -w "%{http_code}" "${BASE}${path}")
  echo "${BASE}${path} → ${STATUS}"
  test "$STATUS" = "200" || { echo "FAIL: ${BASE}${path} returned ${STATUS}"; exit 1; }
done

# === Anchor 4: /sitemap.xml correct hostname; MiniSearch enabled ===

curl -fsS "${BASE}/sitemap.xml" | grep -F "https://progresslabit.github.io/progress-platform/"
curl -fsS "${BASE}/" | grep -E "VPLocalSearch|provider.+local" || \
  curl -fsS "${BASE}/" | grep -F 'minisearch'

# === Anchor 3: Top-nav shows API · Events · CLI · Users · Admins ===
# VitePress renders nav links inside <a class="VPNavBarMenuLink"> ... <span class="text">LABEL</span> ... </a>.
# Naive ">LABEL<" matching false-passes against homepage hero text ("API Reference" etc.).
# Anchor the check to the VPNavBar region and to the VPNavBarMenuLink class so only nav-rendered
# labels count, not hero / sidebar / link text in the page body.

HOME=$(curl -fsS "${BASE}/")

# Extract the VPNavBar region (greedy enough to capture the nav links inside)
NAV=$(printf '%s' "$HOME" | tr -d '\n' | grep -oE '<div[^>]*class="[^"]*VPNavBar[^"]*"[^>]*>.*</nav>' | head -1)
if [ -z "$NAV" ]; then
  # Fallback: parse the built dist/index.html if the live site nav couldn't be isolated
  NAV=$(tr -d '\n' < docs/.vitepress/dist/index.html | grep -oE '<div[^>]*class="[^"]*VPNavBar[^"]*"[^>]*>.*</nav>' | head -1)
fi
[ -n "$NAV" ] || { echo "FAIL: could not isolate VPNavBar region from rendered HTML"; exit 1; }

for label in API Events CLI Users Admins; do
  printf '%s' "$NAV" | grep -qE "VPNavBarMenuLink[^>]*>[^<]*(<[^>]+>[^<]*)*${label}" \
    || { echo "FAIL: nav label ${label} missing from VPNavBar"; exit 1; }
done

# === Anchor 5: lychee runs on DEV + PRs; --include-fragments + --root-dir + --base ===

# Workflow triggered on the same mirror push
gh run list --repo ProgressLabIT/progress-platform --workflow=lychee.yml --branch=DEV --limit 1 \
  --json conclusion | jq -e '.[0].conclusion == "success"'

# Workflow file actually contains the required flags
gh api /repos/ProgressLabIT/progress-platform/contents/.github/workflows/lychee.yml \
  -H "Accept: application/vnd.github.raw" \
  | grep -F -- "--include-fragments"
gh api /repos/ProgressLabIT/progress-platform/contents/.github/workflows/lychee.yml \
  -H "Accept: application/vnd.github.raw" \
  | grep -F -- "--root-dir"
gh api /repos/ProgressLabIT/progress-platform/contents/.github/workflows/lychee.yml \
  -H "Accept: application/vnd.github.raw" \
  | grep -F -- "--base"

# === Anchor 5: openapi.json build artefact slot exists in dist ===
# Per ROADMAP success criterion #5 the artefact MUST be produced and served at site root.
# VitePress copies docs/public/* → dist/* by spec, so the placeholder MUST be reachable in Phase 1.

HTTP=$(curl -fsS -o /dev/null -w "%{http_code}\n" "${BASE}/openapi.json")
[ "$HTTP" = "200" ] || { echo "FAIL: openapi.json placeholder not served (got $HTTP)"; exit 1; }

# === SITE-08: source-code permalinks → github.com (lychee crawl is the live test) ===
# Sample any rendered "Edit this page" link in the dist:
curl -fsS "${BASE}/" | grep -F "github.com/ProgressLabIT/progress-platform/edit/DEV/docs/"
! curl -fsS "${BASE}/" | grep -F "gitlab.com"

# === Branch ruleset status checks now active ===

gh api /repos/ProgressLabIT/progress-platform/commits/DEV/check-runs \
  --jq '.check_runs[] | select(.name == "build" or .name == "linkChecker") | "\(.name):\(.conclusion)"' \
  | sort -u
# expected output:
# build:success
# linkChecker:success

# === Mirror sync after the workflow files landed ===

GL_SHA=$(git ls-remote https://gitlab.com/progresslab/progress-platform DEV | awk '{print $1}')
GH_SHA=$(git ls-remote https://github.com/ProgressLabIT/progress-platform DEV | awk '{print $1}')
test -n "$GL_SHA" && test "$GL_SHA" = "$GH_SHA"
```
